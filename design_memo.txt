For the undo and redo system, a stack makes the most sense because actions need to be handled in the opposite order that they were added. The most recent action should always be the first one that gets undone. This follows the last in, first out idea. When an action is performed, I push it onto the undo stack. If the user chooses undo, I pop the most recent action off the undo stack and move it onto the redo stack. Redo works the same way but moves the action back to the undo stack.

A queue works better for the help desk because customers should be helped in the same order they entered. The first customer added should also be the first customer removed. This follows the first in, first out idea. New customers are added at the rear of the queue while the customer being helped is removed from the front.

My implementations are different from Python's built in lists because I created the structures myself using Node objects and pointers. Each Node stores a value and a reference to the next Node. The Stack only keeps track of the top, while the Queue keeps track of both the front and rear. Python lists already have methods that could imitate stack and queue behavior, but building them myself helped show how the structures actually manage and access their data.
